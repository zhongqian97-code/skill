# Personal Skills

这是一个个人 Agent Skill 集合，用来沉淀可复用的工作方法。每个 Skill 都把一类任务的触发条件、执行流程、质量标准和交付物整理成明确规则，便于在不同项目中重复使用。

## Skill 总览

| Skill | 主要作用 | 适用场景 | 主要产出 |
| --- | --- | --- | --- |
| [ai-delivery-loop](skills/ai-delivery-loop/) | 把一个需求从澄清、方案设计、实现、验收带到评审闭环 | 需求还不清晰，且希望由同一套流程完成完整交付 | 调研说明、设计文档、测试、实现、验收映射和评审结论 |
| [detailed-design-writing](skills/detailed-design-writing/) | 编写或改进可通过实现就绪门禁的详细设计 | 设计必须在编码前闭合需求、契约、数据、异常、安全、验证与交付证据 | 版本化详细设计、追踪矩阵、跨层契约、失败恢复、测试与 Review Handoff |
| [review-detailed-design](skills/review-detailed-design/) | 用硬门禁、证据评分和缺陷分级审核详细设计是否可以进入实现 | 每一份详细设计完成后、编码开始前，以及关键设计变更后 | PASS / CONDITIONAL PASS / FAIL、实现授权、缺陷与复审清单 |
| [learn-feature](skills/learn-feature/) | 帮助学习者真正掌握一个新特性的需求、架构、规则和边界 | 需要学习 PRD、设计、代码或测试，而不只是阅读摘要 | 一页心智模型、掌握度诊断、主动回忆卡和复习计划 |

## ai-delivery-loop

### 有什么作用

为一个需求建立完整交付闭环：先研究并消除需求歧义，再比较方案、编写设计、通过测试驱动实现，最后把设计、代码、测试和人工验证逐项对应起来，并将评审发现反馈到设计和实现中。

### 什么时候使用

- 需求只有大致方向，需要继续澄清目标、范围和验收标准。
- 希望比较原型方案、工程化方案和行业常见方案。
- 任务需要同时覆盖设计、编码、测试、验收和评审。
- 担心设计与实现脱节，或评审问题没有形成闭环。

### 使用后会得到什么

- 清晰的需求假设、范围边界和未解决风险。
- 多层次方案对比与推荐结论。
- 包含异常路径和测试策略的统一设计。
- 设计项、代码位置、测试和人工验证之间的对应关系。
- 经评审迭代后可交付、可追踪的完整结果。

## detailed-design-writing

### 有什么作用

帮助编写、补充或重构实现就绪的详细设计。它保留“现状—目标—差距—实现映射”，并进一步要求稳定需求 ID、跨层契约、数据与状态不变量、异常恢复、质量指标、安全控制、确定性测试、上线回滚和运行证据，使实现者无需在编码阶段补做关键设计。

### 什么时候使用

- 从零编写详细设计，或将已有方案说明升级为实现级设计。
- 需要把需求和验收条件追踪到模块、UI/API/Event/Data/State、测试与运行证据。
- 涉及并发、消息、缓存、数据迁移、权限、安全、容量、SLO、发布或恢复等高风险设计。
- 需要在独立 Review 前完成 readiness 自检并冻结证据版本。

### 使用后会得到什么

- 带来源状态、版本和适用性声明的详细设计。
- 需求—设计—契约/数据/状态—测试—运行证据追踪矩阵。
- 正常、失败、并发、重试、部分成功、重启和恢复流程。
- 可执行的接口/事件/数据契约、质量场景、安全与交付方案。
- 明确标记 `Ready for independent review` 或 `DRAFT — NOT READY FOR FORMAL REVIEW` 的 Review Handoff。

Writing Skill 不授予实现权限。文档仍需由 `review-detailed-design` 独立评审，只有取得 `PASS` 后才能进入开发。

## review-detailed-design

### 有什么作用

作为详细设计进入实现前的独立质量门禁。它先检查文档是否达到正式评审入口，再审查范围追踪、跨层契约、数据与一致性、失败恢复、质量指标、安全、测试和发布运维。总分不能抵消硬门禁或严重缺陷。

### 什么时候使用

- 每一份详细设计完成后、编码开始前。
- API、数据、状态、安全边界、质量目标、迁移、上线或回滚方案发生关键变化后。
- 需要判断文档是否已经详细到“实现者不必再做关键设计”。

### 使用后会得到什么

- `PASS`、`CONDITIONAL PASS` 或 `FAIL`，以及明确的实现授权状态。
- 带证据位置的九项硬门禁和九维评分。
- S0–S4 缺陷、精确补充要求、责任人、期限和复核方式。
- 需求—设计—测试—运行证据追踪表和复审范围。

## learn-feature

### 有什么作用

把 PRD、设计文档、Issue、接口、测试和核心代码等资料转化为可复述、可推演、可迁移的心智模型。它以主动回忆为主，通过预测、核对、微解释、复述和迁移练习判断学习者是否真正掌握，而不是只确认“看懂了”。

### 什么时候使用

- 刚接触一个新特性，需要快速建立整体认识。
- 需要深入掌握主流程、状态、不变量、异常边界和设计取舍。
- 已经学过某个特性，希望针对薄弱点复习。
- 准备开发、测试、评审或讲解某个功能，需要验证自己能否脱离资料复述。
- 希望把易错点整理为后续可复习的主动回忆卡片。

### 使用后会得到什么

- 带来源状态的一页特性心智模型。
- 对“稳固、模糊、误解、未知”的掌握度诊断。
- 对主流程、规则、状态和边界的场景化练习与验收。
- 错误与误解清单，以及 5–15 张主动回忆卡。
- 按本轮结束、1 天、3 天、7 天、14 天安排的复习建议。

## 如何使用

1. 选择与当前任务最匹配的 Skill 目录。
2. 将该目录放入支持 Agent Skills 的工具或 Agent 的 Skill 搜索路径中。
3. 确保 `SKILL.md` 及其 `references/`、`templates/` 等配套文件保持原有相对目录结构。
4. 用自然语言提出符合适用场景的任务，并提供必要的项目资料、文件路径或目标说明。

不同 Agent 平台的安装位置和加载方式可能不同，请以所用平台的 Skill 文档为准。

## 目录结构

```text
skills/
├── ai-delivery-loop/
├── detailed-design-writing/
├── review-detailed-design/
└── learn-feature/
```

每个目录的 `SKILL.md` 是该 Skill 的入口；`references/` 保存补充方法，`templates/` 保存可复用模板。
