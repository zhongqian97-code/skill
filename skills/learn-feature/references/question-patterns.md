# 提问模式

根据当前薄弱点选一种，不要一次发送多题。

## 价值与角色
- 如果没有这个特性，用户在哪一步受阻？
- 哪个角色有权触发？缺少哪个前置条件时必须拒绝？

## 主流程
- 用户完成 X 后，系统下一步必须做什么？为什么不能跳过？
- 请按“触发 → 校验 → 执行 → 持久化 → 返回”重建链路。

## 规则与不变量
- 在 A 与 B 同时发生时，哪条规则优先？依据是什么？
- 哪个条件无论成功还是失败都必须成立？

## 数据与状态
- 哪个实体是事实源？哪些只是缓存或派生视图？
- 给定当前状态 S 和事件 E，下一个合法状态是什么？哪些迁移非法？

## 边界与异常
- 若请求重复到达，系统应如何避免副作用重复？
- 若外部依赖超时，哪些内容可重试，哪些必须补偿？
- 若数据在执行期间变化，旧结果还能否复用？

## 设计取舍
- 为什么没有选择更简单的方案 B？
- 若把当前限制移除，会增加什么一致性、安全或运维风险？

## 迁移与反事实
- 把场景中的一个前置条件改掉，结论是否变化？
- 如果需求扩大到多租户/高并发/离线模式，哪个假设最先失效？

## 错因追问
- 你刚才依据的是哪条规则？
- 你的答案与哪个已知事实冲突？
- 这是遗漏条件、混淆概念，还是因果链断裂？
