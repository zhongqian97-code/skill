# Learn Feature

把特性资料转化为学习者可复述、可推演、可迁移的心智模型。以主动回忆为主，解释为辅；不要用长篇总结代替学习。

## 原则

- 使用用户语言教学。
- 只依据提供的文档、代码和已验证来源；标注“明确规定”“代码验证”“合理推断”“尚未确定”。
- 一次只提出一个主要问题，并等待学习者作答。
- 先让学习者预测或回忆，再解释答案。
- 答错时先指出矛盾或缺口，让学习者重答；第二次仍错再给最小必要解释。
- 不把“看懂答案”当作掌握；以脱离资料后的复述、场景推演和边界判断为准。
- 默认只教学，不修改产品代码。除非用户另行要求，不把学习流程切换为实现流程。

## 选择模式

根据用户时间与目标选择：

- **overview**：约 10 分钟，建立全貌；覆盖核心目标、主流程、关键规则和最大风险。
- **mastery**：约 30–60 分钟，完整掌握；加入状态、异常、权衡、代码落点和综合案例。
- **refresh**：复习已学内容；从旧卡片和薄弱点开始，不重新讲完整课程。

用户没有指定时，先说明将采用 overview，并允许其随时切换。不要为了确认模式而阻塞已经明确的学习请求。

## 阶段一：建立可信知识地图

读取用户指定资料。资料路径不明确时，先在当前项目中定位 PRD、设计文档、Issue、ADR、API/schema、相关测试与核心实现；必要时询问一个最关键的来源问题。

提取八格特性地图：

1. **问题与价值**：为什么做，解决谁的什么问题。
2. **角色与前置条件**：谁触发，权限、依赖和入口是什么。
3. **主链路**：从输入到结果的正常流程。
4. **规则与不变量**：任何情况下都必须成立的约束。
5. **数据与状态**：关键实体、输入输出、状态迁移和持久化。
6. **边界与异常**：失败、超时、重试、幂等、并发、降级和限制。
7. **系统影响**：涉及的模块、API、任务、工具、存储和观察面。
8. **设计取舍**：为什么采用当前方案，替代方案及代价。

先内部整理，再向学习者展示一份不超过 12 条的“一页心智模型”。每条保留来源位置；不确定项进入“待确认”。

详细工作表格式见 [templates/feature-learning-sheet.md](templates/feature-learning-sheet.md)。

## 阶段二：诊断已有理解

要求学习者用 60–90 秒回答：

> 不看资料，请用自己的话说明：这个特性解决什么问题、主流程怎么走、最重要的规则是什么？

根据回答建立掌握度矩阵：

- **稳固**：能准确回忆，并能用于新场景。
- **模糊**：方向正确但缺关键条件或因果链。
- **误解**：与资料或代码证据冲突。
- **未知**：尚未接触。

只补“模糊、误解、未知”，不要重复讲已稳固内容。

## 阶段三：教与练循环

按依赖顺序教学：价值 → 主流程 → 规则 → 状态 → 边界 → 取舍。

每个概念运行同一循环：

1. **预测**：给出一个小场景，让学习者先判断会发生什么以及为什么。
2. **核对**：对照来源指出正确部分和缺口。
3. **微解释**：用最短解释补足因果链；必要时给一个类比。
4. **回忆**：隐藏答案，让学习者用自己的话重述。
5. **迁移**：改变一个条件，检查能否应用规则而非背句子。

问题模式见 [references/question-patterns.md](references/question-patterns.md)。不要连续抛出问题列表。

每完成 3 个概念，做一次闭卷总结检查，让学习者复述它们之间的关系。

## 阶段四：掌握度验收

至少完成以下三项：

1. **两分钟复述**：不看资料完整说明问题、主流程、规则和异常。
2. **链路重建**：用文字或图重建主流程与关键状态。
3. **边界案例**：处理一个包含异常或冲突条件的新场景，并说明依据。

mastery 模式再增加：

4. **反事实问题**：若移除某条规则或换一种设计，会造成什么后果。
5. **代码落点**：把需求概念映射到接口、模块、测试或观测指标。

判定：

- 三项均正确且无关键遗漏：已掌握。
- 主流程正确但边界/取舍薄弱：基本掌握，生成针对性复习。
- 仍依赖提示或存在核心误解：未掌握，返回最小薄弱环节继续一轮。

不要因为学习者说“懂了”就提前通过。

## 阶段五：生成主动回忆卡

课程结束后生成 5–15 张卡片，优先覆盖：

- 为什么与因果关系
- 不变量和触发条件
- 状态迁移
- 易混淆边界
- 设计取舍
- 学习者实际答错的内容

卡片格式：

```text
Q: <脱离上下文仍清晰的问题>
A: <简洁准确答案>
Evidence: <文件、章节、代码位置或来源 URL>
Tag: <feature>/<主题>
Difficulty: easy|medium|hard
```

避免“这个是什么？”之类依赖当前上下文的问题。答案必须能被来源验证。

建议复习节奏：本轮结束、1 天、3 天、7 天、14 天。refresh 模式先抽查到期卡片，答对则提高难度或延长间隔，答错则记录错因并缩短间隔。

## 最终交付

在学习互动完成后，给出：

- 一页心智模型
- 掌握度矩阵
- 错误与误解清单
- 主动回忆卡
- 下一次复习时间与重点
- 仍待确认的资料问题

如果用户中途暂停，输出一个简短学习断点：已掌握、未掌握、下一题和所用来源，便于下次继续。
